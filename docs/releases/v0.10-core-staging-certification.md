## How to complete this record

Each proof item has a stable evidence ID. Store raw logs, screenshots, exports,
manifests, and test reports in an access-controlled immutable artifact store;
do not commit secrets or production data. The canonical evidence prefix is:

```text
v0.10.0-rc.8/cdaa910/<workflow-run-id>/<run-attempt>/
```

Every evidence row must contain an immutable URL (or content-addressed object
reference) beneath that prefix, a 64-character lowercase SHA-256 digest, UTC
collection time, an owner, and a result. The raw artifact may be grouped under
`artifacts/<evidence-id>/`, but the evidence index is the only source of the
ID-to-artifact mapping. Replace the angle-bracket fields with recorded values;
`PENDING` is intentionally used until the test has actually run.

The workflow must never overwrite an existing object key. Uploads use S3
Object Lock in `COMPLIANCE` mode with seven-year retention, and the retention
metadata must be checked on every object, including the index and digest
manifest.

### Machine-readable evidence index

The canonical machine-readable registry is
`scripts/staging-certification-contract.json`; it defines all 25 rows and the
`ENV-003`/`ENV-004` control aliases. The certification workflow must produce
exactly one automated `evidence-index.json` for each run and upload it beneath
the candidate prefix. The automated index is generated from structured test
output plus deployment metadata; the release owner then merges the
operator-lane records with `scripts/staging-certification-closeout.sh` into the
same validated index. Hand-edited rows are not accepted. Each `entries[]` object must contain these
fields:

```json
{
  "evidence_id": "J-ARAP-001",
  "result": "PASS",
  "run_id": "<workflow-run-id>",
  "collected_utc": "<RFC3339 UTC>",
  "details": "<specific observed effects and IDs>",
  "artifact_uri": "s3://<bucket>/<candidate-tag>/<candidate-short-sha>/<run-id>/<attempt>/...",
  "sha256": "<64 lowercase hex characters>"
}
```

The automated validator compares its index to the automated evidence IDs above:
each appears exactly once and no unknown ID is accepted. At closeout, the
release owner validates the merged index against the full registry below,
including the operator IDs. Every result must be `PASS`, `FAIL`, or justified
`N/A`, and every details, URI, timestamp, and hash field must be present. A
final index may not contain `PENDING`. A failed test still produces an index
with `FAIL` and its diagnostic artifact; an early workflow failure must at
least preserve candidate identity, failure logs, and the validation result so
the run is auditable. The index itself and its SHA-256 manifest are evidence
and must be included in the uploaded bundle.

The automated lane is collected with the canonical contract (the workflow
passes `--contract scripts/staging-certification-contract.json --lane
automated`). Once operator evidence is available, close out both lanes with a
write-once merge:

```bash
scripts/staging-certification-closeout.sh \
  --automated automated/evidence-index.json \
  --operator operator/evidence-index.json \
  --output closeout \
  --candidate-tag <candidate-tag> \
  --candidate-sha <40-hex-sha> \
  --prefix <immutable-closeout-prefix>
```

The closeout validator rejects missing, duplicate, unknown, out-of-lane,
unreviewed, mutable, or `PENDING` entries and writes `evidence-index.json` plus
`SHA256SUMS` only once.

Result policy:

- `PASS` means every acceptance criterion in the row is met and the raw
  artifact is reachable at the recorded immutable URL with the recorded hash.
- `FAIL` means the check ran and at least one acceptance criterion was not met;
  a failed required row blocks promotion.
- `N/A` is allowed only for an explicitly out-of-profile capability or
  dependency, and requires route/configuration evidence plus release-owner and
  approver sign-off. `N/A` cannot skip one of the five core journeys or a
  required backup, migration, security, rollback, or observation control.
- `PENDING` means the evidence is not complete. It is not a passing result and
  cannot support a production-certification claim.

No result may be changed to `PASS` without an immutable artifact URL and hash.
Any critical or high finding, candidate identity mismatch, migration above
`000124`, or unresolved required `FAIL`/`PENDING` result is a `NO-GO`.

### Decision and update rules

Record `GO` only when all of the following are true:

- the annotated tag, full SHA, recorded candidate lineage (merge-base
  `04ebd8a` and the 15-commit stabilization chain), `v0.10-core` profile,
  production-tagged artifact digests, route manifest, and migration ceiling
  match this record exactly;
- the evidence index validates with one result for every required ID, all five
  journeys and all required isolation/security/migration controls are `PASS`,
  and every `N/A` has the required route/configuration and approver evidence;
- the operator lane proves environment separation, backup/restore, disposable
  migration recovery, rollback and rc.8 restoration, queue/alert behavior, and
  the complete 60-minute observation window; and
- test, security, operations, and release-owner approvals are attached, with no
  open critical or high finding and no unresolved missing infrastructure.

After `GO`, update this record from the immutable evidence index, then commit a
single reviewed closeout change that updates the five scoped feature-matrix rows, the
Roadmap Milestone 1/2 checkboxes, the production release checklist, and version
history. Keep `production-certified=no` until the separate production gate and
signed final release decision pass. Do not move or recreate `v0.10.0-rc.8`.

Record `NO-GO` for any identity mismatch, missing preflight input, invalid or
incomplete evidence index, required `FAIL`/`PENDING`, migration above `000124`,
failed operator control, or open critical/high finding. Preserve that run's
immutable bundle and index, add a finding with owner, disposition, and due date,
and leave all five matrix rows `production-certified=no`. Fix the application or
certification tooling on a descendant commit and create a new release candidate;
never overwrite, move, or retag rc.8 and never replace a failed artifact in
place.

While a run is in progress, only the evidence owner may fill the corresponding
row and only a reviewer may change its result to `PASS`/`N/A`; the registry and
human-readable tables must agree with the validated index. A missing artifact,
hash, reviewer, or operator control remains `PENDING` and blocks promotion.

Until this section is complete, the candidate remains a release candidate and
all five in-scope feature-matrix rows remain `production-certified=no`. The
final gate must run from a clean, tagged checkout after the evidence record is
completed. Supply the local write-once closeout index and its immutable URI;
the gate verifies the 25-row contract, local `SHA256SUMS`, S3 reachability, and
COMPLIANCE Object Lock metadata for the index, manifest, and every artifact:

```bash
RELEASE_PROFILE=v0.10-core \
CERTIFICATION_EVIDENCE_INDEX_FILE=/secure/evidence/evidence-index.json \
CERTIFICATION_EVIDENCE_INDEX_URI=s3://<bucket>/<candidate-tag>/<short-sha>/<run>/<attempt>/evidence-index.json \
EVIDENCE_S3_ENDPOINT=<object-lock-endpoint> \
EVIDENCE_S3_REGION=<region> \
EVIDENCE_S3_ACCESS_KEY_ID=<managed-secret> \
EVIDENCE_S3_SECRET_ACCESS_KEY=<managed-secret> \
make production-release-check
```
