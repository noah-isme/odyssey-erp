# v0.10-core Staging Certification Record

**Status:** Evidence template; this record is not a certification or a release
approval until every required result is reviewed and approved below.

**Profile:** `v0.10-core`

**Candidate:** `v0.10.0-rc.4`

**Application baseline:**
`ec65cc08639c184030c63e3407791987eee92804`

The annotated `v0.10.0-rc.4` tag is the authority for the exact candidate
commit. That commit packages the application baseline above with release-only
documentation and automation changes; it is not expected to have an SHA that
begins with `ec65cc0`.
The staging deployment must set `RELEASE_PROFILE=v0.10-core`. The profile
claims only the five capabilities marked `v0.10.0 scope=yes` in the
[authoritative feature matrix](../reference/feature-matrix.md). The candidate
must contain migrations through `000124` and must not contain migration
`000125` or v0.11 finance routes. A capability may be marked
`production-certified=yes` only after its evidence is attached to this record
and reviewed by the release owner.

## How to complete this record

Each proof item has a stable evidence ID. Store raw logs, screenshots, exports,
manifests, and test reports in an access-controlled immutable artifact store;
do not commit secrets or production data. Use the following object-key pattern:

```text
v0.10.0-rc.4/<candidate-commit>/<evidence-id>/<artifact-name>
```

Every evidence row must contain an immutable URL (or content-addressed object
reference), a 64-character lowercase SHA-256 digest, UTC collection time, an
owner, and a result. Replace the angle-bracket fields with recorded values;
`PENDING` is intentionally used until the test has actually run.

Result policy:

- `PASS` means every acceptance criterion in the row is met and the raw
  artifact is reachable at the recorded immutable URL with the recorded hash.
- `FAIL` means the check ran and at least one acceptance criterion was not met;
  a failed required row blocks promotion.
- `N/A` is allowed only for an explicitly out-of-profile capability or
  dependency, and requires route/configuration evidence plus release-owner and
  approver sign-off. Prefix its evidence registry Required proof value with
  `N/A: ` and the reason. `N/A` cannot skip one of the five core journeys or a
  required backup, migration, security, rollback, or observation control.
- `PENDING` means the evidence is not complete. It is not a passing result and
  cannot support a production-certification claim.

No result may be changed to `PASS` without an immutable artifact URL and hash.
Any critical or high finding, candidate identity mismatch, migration above
`000124`, or unresolved required `FAIL`/`PENDING` result is a `NO-GO`.

## Tenant and access isolation

Use at least two companies and two branches, for example `COMPANY-A` with
`BRANCH-A1`/`BRANCH-A2` and `COMPANY-B` with `BRANCH-B1`. Record the actual
non-production IDs in the evidence artifacts. Every case must verify both the
HTTP response and the absence of a persistence, ledger, inventory, document,
or worker side effect in the other scope.
