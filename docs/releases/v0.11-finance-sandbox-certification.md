## Evidence rules

Store raw logs, screenshots, database checks, queue traces, metric captures, and
provider reports in an access-controlled immutable store. Every evidence row
must include an immutable URL or content-addressed object reference, a lowercase
64-character SHA-256 digest, UTC collection time, owner, reviewer, and result.
`PENDING` is not a passing result. A required `FAIL`, unresolved high/critical
finding, identity mismatch, or migration below `000128` is a `NO-GO`.

Use this object-key pattern:

```text

```

## Local and sandbox commands

The workflow runs the following deterministic contract set before artifact
creation. Repeat these commands locally from the candidate checkout and attach
the output under `PROV-002`, `REC-002`, and `OPS-002`:

```bash
go test ./internal/connectors/providers/midtransiris -count=1
go test ./internal/connectors/providers/midtrans -run '^TestMidtransSandboxCertification$' -count=1
go test ./internal/finance/payments -run 'Test(PaymentRecovery|CoordinatorResolvesAmbiguous|PaymentExecutionOutboxAmbiguous|PaymentResultImportOutbox)' -count=1
go test ./internal/observability -run '^TestPaymentRecoveryMetricsExposeRecoverySignals$' -count=1
go test ./jobs -run '^TestHandleFinancePaymentRecoveryScan' -count=1
```

The isolated deployment must additionally prove the following live cases:

1. Submit a payout, force a response timeout after provider acceptance, and
   show one provider lookup before any resubmission.
2. Deliver duplicate and out-of-order provider results; show one result key,
   one effect key, one AP/GL/tax/bank effect set, and stable effect links.
3. Produce partial, failed, cancelled, unapplied-effect, unmatched, and
   dead-letter cases; show operator notifications only for the owning company.
4. Exercise explicit recovery through the operations workbench, preserving the
   original correlation and recording replay lineage. No manual settlement
   override or blind retry is permitted.
