# Odyssey ERP v0.10.0-rc.2 — 2026-08-10

**Status:** Release candidate; not production-certified.

This candidate supersedes `v0.10.0-rc.1` with the Coretax and Indonesian PPh 21
release-test work. It packages the post-v0.9.1 platform work for staging review;
it is not a production approval.

## Changes since rc.1

- Coretax submission and export validation now use an explicitly configured HTTP
  endpoint and fail closed on missing configuration, transport errors, rejected
  responses, or invalid response bodies.
- The local tax release suite proves reviewed XML export, validator acceptance,
  persisted totals, and zero-difference GL reconciliation.
- Annual PPh 21 now has a versioned, integer-rupiah last-tax-period calculation
  with progressive bands, prior withholding, signed December corrections, and a
  checked-in PMK 168/2023 worked-example fixture.
- The previous advanced document, CMMS, MRP, distribution, finance, connector,
  repository-boundary, HTTP-error, and release-gate work remains included.

## Verification

The candidate's local verification includes:

- `go test ./internal/payroll ./internal/tax`;
- the full Go test suite and `go vet`;
- Linux `production` build;
- `production pdf` tests and build;
- `golangci-lint`; and
- documentation, release-claim, and advertised-route placeholder checks.

## Remaining promotion gates

- The local Coretax contract test does not replace official DJP
  XSD/converter validation or a Coretax staging/import acceptance record.
- The annual PPh 21 fixture is a reviewed calculation regression test; the
  effective production rule version and company payroll evidence still require
  payroll/legal sign-off.
- No capability is production-certified until staging, provider, migration,
  security, and operational evidence is recorded in the feature matrix.
- Production deployment is self-managed on a VPS; use the VPS deployment runbook
  and complete its operator evidence before promotion.
- PDF routes require the `production pdf` build tags and a reachable Gotenberg
  service.

## Upgrade and deployment notes

Apply migrations through the normal controlled migration process, including the
document/CMMS completion migration `000117` and MRP compliance hardening
migration `000118`. Deploy web and worker artifacts from the same candidate
commit. Use the [Production Release Checklist](production-release-checklist.md)
for staging, backup/restore, smoke, rollback, and final promotion evidence.
