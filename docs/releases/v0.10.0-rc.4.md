# Odyssey ERP v0.10.0-rc.4 — 2026-08-12

**Status:** Release candidate; not production-certified.

**Application baseline:**
`ec65cc08639c184030c63e3407791987eee92804`

**Candidate commit:** Resolved by the annotated `v0.10.0-rc.4` tag after this
release packaging is committed.

**Release profile:** `v0.10-core`

**Migration ceiling:** `000124_scoped_rbac_global_compatibility`

This candidate packages the reviewed application baseline with the release
documentation and automation needed for staging certification. The annotated
tag is the authority for the exact candidate SHA; the application baseline SHA
is not reused as a self-referential packaging commit. This candidate does not
certify any capability for production and must not be treated as the final
`v0.10.0` release.

## Changes since rc.3

- Made migration, migration-status, migration-safety, and seed runbook targets
  executable and documented their production-safe usage.
- Updated the release gates to require tagged-candidate identity and reject
  incomplete staging certification evidence.
- Kept generated SQLC bindings current with the application baseline.
- Fixed the remaining Midtrans lint issue required by the release checks.
- Added component checksums, migration and web manifests, an SPDX SBOM, and a
  GitHub build-provenance attestation for the immutable release bundle to the
  staging artifact workflow.

## Verification and remaining gates

Deploy and certify the commit resolved by the annotated `v0.10.0-rc.4` tag in
an isolated staging environment with `RELEASE_PROFILE=v0.10-core`. Record the
tag object, resolved candidate SHA, relationship to the application baseline,
CI run, artifact digests, SBOM digest, provenance attestation, and deployed
revision in the staging certification record.

The five core journeys, migration and backup restore, scoped-access negative
tests, operational controls, rollback, and required profile-scoped external
gates remain open until their evidence is recorded.

Run the final gate only after staging evidence is complete:

```bash
RELEASE_PROFILE=v0.10-core make production-release-check
```

Until that gate and the release-owner go/no-go decision pass, all v0.10-core
feature-matrix rows remain `production-certified=no`.
