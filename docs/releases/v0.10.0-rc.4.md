# Odyssey ERP v0.10.0-rc.4 — 2026-08-12

**Status:** Superseded release candidate; not production-certified.

**Superseded by:** `v0.10.0-rc.6`, whose exact candidate commit is `d8b02b8`.

**Candidate commit:** `ec65cc08639c184030c63e3407791987eee92804`

**Release profile:** `v0.10-core`

**Migration ceiling:** `000124_scoped_rbac_global_compatibility`

This candidate was frozen from the reviewed `ec65cc0` baseline for v0.10-core
staging certification. It packages the five bounded v0.10 capabilities and the
release-gate hardening completed after rc.3. It was superseded before
production certification by rc.5 and then rc.6; it must not be treated as the
current or final `v0.10.0` release.

## Changes since rc.3

- Made migration, migration-status, migration-safety, and seed runbook targets
  executable and documented their production-safe usage.
- Updated the final release gate to require exact tagged-candidate identity and
  reject incomplete staging certification evidence.
- Kept generated SQLC bindings current with the release baseline.
- Fixed the remaining Midtrans lint issue required by the release checks.
- Retained the self-managed VPS deployment target, bounded route profile, and
  evidence-based production status from rc.3.

## Candidate boundary

The rc.4 candidate includes source and migrations through commit
`ec65cc08639c184030c63e3407791987eee92804` and migration
`000124_scoped_rbac_global_compatibility`. The later v0.11-finance implementation
commit `1a8343e4499420467ba3dda04a2683782c6c79d7`, migration
`000125_payment_settlement_results`, and v0.11-only finance routes are excluded
from this v0.10-core candidate and remain on the next-release line.

## Verification and remaining gates

The candidate must be deployed and certified from the exact tagged commit in an
isolated staging environment with `RELEASE_PROFILE=v0.10-core`. The five core
journeys, migration/backup restore, scoped-access negatives, artifact identity,
operational controls, rollback, and required profile-scoped external gates remain
open until recorded in the [staging certification record](v0.10-core-staging-certification.md).

Run the final gate only after the staging evidence is complete:

```bash
RELEASE_PROFILE=v0.10-core make production-release-check
```

Until that gate and the release-owner go/no-go decision pass, all v0.10-core
feature-matrix rows remain `production-certified=no`.
