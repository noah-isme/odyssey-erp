# Odyssey ERP v0.10.0-rc.1 — 2026-08-10

**Status:** Release candidate; not production-certified.

This candidate packages the post-v0.9.1 platform work for staging review. It is
not a production approval: the [authoritative feature matrix](../reference/feature-matrix.md)
still records open certification and integration gates.

## Scope

- Advanced document foundations: asynchronous OCR jobs with an injectable text
  extractor, tenant-scoped content search, persisted collaboration sessions and
  changes, retention expiry, legal-hold checks, and approved disposition execution.
- CMMS advanced foundations: persisted IoT readings, predictive-model metadata,
  company-scoped anomaly alerts, and idempotent worker-compatible operations.
- MRP governance controls: canonical database snapshots, stable record versions and
  hashes, policy-role and separation-of-duties enforcement, one-time actor-bound
  challenges, password/TOTP reauthentication, immutable evidence, and retention data.
- Previously packaged platform work: distribution lifecycle, finance automation,
  freight/logistics foundations, hardened connectors, repository-owned SQLC
  boundaries, and shared HTTP error handling.
- Release hygiene: authoritative four-dimensional feature matrix, production-tagged
  build checks, PDF build verification, lint/vet gates, and the final release checklist.

## Verification completed

The candidate commit passes the local repository gates:

- full Go test suite;
- `golangci-lint`;
- `go vet`;
- Linux `production` build;
- `production pdf` tests and build;
- documentation, release-claim, and advertised-route placeholder checks.

## Known limitations and promotion gates

- No capability is production-certified until staging, provider, migration, security,
  and operational evidence is recorded in the feature matrix.
- Coretax validation and the approved December PPh 21 reconciliation fixtures remain
  explicit blocked release tests.
- Provider sandbox/limited-production certification, live bank-feed/payment operation,
  scanned-document OCR, real predictive inference, and deeper downstream MRP policy
  enforcement remain outside this candidate's certification evidence.
- `render.yaml` is a Free demo/staging blueprint and is not a production deployment
  definition.
- PDF routes require the `production pdf` build tags and a reachable Gotenberg service.

## Upgrade and deployment notes

Apply migrations through the normal controlled migration process, including the
document/CMMS completion migration `000117` and MRP compliance hardening migration
`000118`. Deploy web and worker artifacts from the same candidate commit. Use the
[Production Release Checklist](production-release-checklist.md) for staging,
backup/restore, smoke, rollback, and final promotion evidence.
